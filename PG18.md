# PostgreSQL 18 syntax

pg_query_go v18 parses SQL with the PostgreSQL 18 grammar. pg_query_go v6
used the PostgreSQL 17 grammar, so a desired file that used syntax added in
PostgreSQL 18 failed to parse. That syntax now parses, and this file records
what pistachio does with each form and what is left to support. Each form is
added on its own, behind its own change.

## Rejected

The model has no place for these forms. Reading them as something else would
plan the wrong DDL, so the parser rejects them.

### NOT NULL as a table constraint

`CREATE TABLE t (a int, CONSTRAINT n NOT NULL a)` and
`ALTER TABLE t ADD CONSTRAINT n NOT NULL a [NOT VALID]` are errors. Before
the rejection, the first read the column as nullable and the second crashed.

The model keeps NOT NULL on the column, as `Column.NotNull` and
`Column.NotNullName`. Supporting the form means folding it into the column.
`NOT VALID` has no counterpart in the model.

### VIRTUAL generated columns

`GENERATED ALWAYS AS (expr) VIRTUAL` is an error. So is
`GENERATED ALWAYS AS (expr)` with no kind, which PostgreSQL 18 makes
virtual. Before the rejection, both were read as `STORED`.

The catalog already reads `attgenerated = 'v'` as `virtual`. Supporting the
form means setting `ColumnGenerated('v')` from `Constraint.GeneratedKind` in
`parseColumnDef`, and checking what the diff does when a column changes
between stored and virtual, which PostgreSQL cannot do in place.

## Parsed, not verified

These forms parse, and the constraint's definition keeps them as text. No
fixture checks that a plan against a PostgreSQL 18 database comes back clean,
or that `pista dump` writes them back in a form that plans clean.

- `NOT ENFORCED` and `ENFORCED` on a CHECK or foreign key constraint.
- `WITHOUT OVERLAPS` in a primary key or unique constraint.
- `PERIOD` in a foreign key.

`ALTER TABLE ... ALTER CONSTRAINT ... [NOT] ENFORCED` is warned about and
ignored, like other statements pistachio does not read.
